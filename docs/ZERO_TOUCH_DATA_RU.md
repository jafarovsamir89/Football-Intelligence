# FOOTBALL INTELLIGENCE — ZERO-TOUCH DATA REQUIREMENT (2026-11-09)

## Решение пользователя (приоритет выше прежнего CSV-first roadmap)

**Пользователь не будет вручную скачивать CSV, выбирать файлы, добавлять коэффициенты, вбивать прогнозы, создавать базу или нажимать "обновить" каждый день.** APK должен самостоятельно собирать доступные бесплатные *разрешённые* данные и выполнять локальные вычисления. Ручной импорт сохраняется лишь в "Настройки → Дополнительно → Импорт/экспорт"; не является MVP и не блокирует запуск.

Не обещать автоматическое получение того, для чего нет разрешённого, живого, бесплатного источника. При отсутствии цен рынка или чужих прогнозов честно показывать `Нет подтверждённых котировок / прогнозов`, не подставлять вероятности модели как коэффициенты реального букмекера. Не имитировать consensus.

## 1. Первоначальный запуск (без регистрации и настройки)
- Сразу главный экран. Система автоматически получает каталоги лиг/сезонов и доступные данные.
- Без обязательного API-key, Google/OAuth, ручного скачивания или CSV.
- Автоматически загрузить доступную историю результатов перед анализом; показывать статус, количество матчей и дату последнего обновления. При плохой сети использовать офлайн-кэш.
- Позволять открыть приложение до завершения импорта; состояния loading/partial/offline/error должны быть честными.

## 2. Бесплатные keyless провайдеры для первой реализации
A. **OpenLigaDB официальный API**: `/getavailableleagues`, `/getavailableleagues/{season}`, `/getlastchangedate/...`, `/getmatchdata/{leagueShortcut}/{season}`. Документация https://api.openligadb.de/index.html. Никаких фиксированных только `bl1` и `bl2`: подгружать поддерживаемые лиги. Сначала проверять `getlastchangedate` перед полным скачиванием. Не превышать 60 requests/min/IP и избегать избыточных запросов. Детальные пути проверить по текущему OpenAPI.
B. **OpenFootball football.json**: https://github.com/openfootball/football.json , датасеты CC0 из `https://raw.githubusercontent.com/openfootball/football.json/master/{season}/{competition_code}.json`. Есть данные для Premier League `en.1.json`, Bundesliga `de.1.json`, LaLiga `es.1.json`, Serie A `it.1.json` и др., но каждый URL/код обязательно проверить перед включением. Данные автоматически генерируются раз в день, однако upstream-обновления НЕ гарантированы — показывать last-seen. Отличать результаты без exact kickoff (только дата) и не допускать future leakage.
- История 3–5 предыдущих сезонов (по размеру, доступности, происхождению) загружается один раз с ограничением трафика; обновления — только для текущего сезона, разумно 1 раз в сутки, с ETag/If-Modified-Since там, где поддерживается.
- Все доступные данные соответствуют лицензии конкретного набора; хранить attribution/source/version.
C. Дополнительно изучить независимые официальные общедоступные API без ключа и лицензированные датасеты; новые источники принимать только после проверки ToS, объёма данных и freshness.

Никаких неразрешённых парсеров Telegram, OddsPortal, Tipstrr, TipsterWatch; никаких чужих токенов, обходов защиты или платных API под видом бесплатных.

## 3. Архитектура обновления
- `DataSource` abstraction + `ProviderRegistry`, capability flags (schedule, result, statistics, odds, tipster, live), source attribution and freshness.
- WorkManager для best-effort periodic sync с network constraint; также синхронизация на запуске с TTL и запретом параллельных дублей.
- Periodic WorkManager НЕ гарантирует точные интервалы/непрерывную работу на выключенном телефоне. UI показывает последнюю успешную синхронизацию.
- HTTP-кэш, ограничение скорости, таймауты, экспоненциальный backoff, хранить time fetched и source published time, дедупликацию и стабильные provider IDs. Не ломать прежнюю SQLite и пользовательские записи.
- Составлять прогнозы только из завершённых исторических результатов до фактического forecast cutoff.
- При отсутствии точного времени начала исторического матча консервативно сдвигать `available_at` после даты финального результата.

## 4. Автоматический анализ без ручных данных
- По умолчанию запускать локальный market-free baseline: Elo + Poisson/Dixon-Coles только после достаточной истории; выводить вероятности 1X2 и происхождение исходных матчей.
- Не обещать ROI виртуальных ставок без исторически и хронологически корректного settlement. Нет коэффициентов => нет оценки betting EV, CLV или "выгодной ставки", только прогноз вероятности и качество модели.
- Добавить автоматическую проверку модели: walk-forward, Brier/log-loss, размеры выборки, журнал ошибок и отказ от прогноза при недостатке данных.
- Автообновление статусов завершённых матчей и метрик.
- Генерация виртуальных "купон-кандидатов" с чёткой пометкой: без рыночных коэффициентов это подбор исходов, **не букмекерский экспресс**, никакого выдуманного общего коэффициента/доходности.
- Автоматизированный crowd consensus может появиться только с легальным публичным API, позволяющим такое использование. До этого скрыть пустые "готовые прогнозы капперов" из основного сценария.

## 5. UX / acceptance
1. Fresh install → Wi-Fi → открываю APK → за один сеанс вижу несколько международных лиг и импортированную историю без единого обязательного действия.
2. После завершения загрузки и наличия истории вижу автоматически рассчитанные 1X2 прогнозы и объяснение модели (или честный "недостаточно данных").
3. Закрываю приложение, открываю снова → локальные данные сразу, затем best-effort refresh при интернет-соединении.
4. Нет интернета → офлайн-кэш; нет данных → понятная ошибка, а не пустой экран без объяснения.
5. Пользователь **никогда** не обязан указывать CSV, токены, bookmaker odds, tipster picks для работы основного приложения.
6. Синхронизация не расходует чрезмерно сеть/батарею и не обходит ограничения поставщиков.
7. Unit tests на JSON parser, duplicate merge, stable IDs, parser fail cases, as-of cutoff, offline fallback, WorkManager worker; GitHub CI assembleDebug + tests green.
8. На главном экране видны: источник, время обновления, качество истории, статус автоматической синхронизации.

## 6. Порядок реализации агенту
- Аудитировать текущие ручные CSV, quotes, picks, и существующий OpenLigaDB-only importer; не удалять их из SQLite. Перевести CSV UI из главного экрана в advanced menu.
- Реализовать отдельный официальный keyless провайдер OpenFootball JSON с тестами на реальных фикстурах и текущем сезоне; встроить загрузку минимум четырёх доступных лиг.
- Затем OpenLigaDB league discovery и `getlastchangedate`/sync.
- Затем автоматический запуск и WorkManager, UI of refresh/cache and reliable as-of model.
- Затем проверенная head-to-head/форма и купоны-кандидаты без фиктивных цен.
- Фиксировать все изменения в DEVELOPMENT_LOG, коммитить, прогонять тесты и GitHub Actions; итог — ссылка на реально собранный APK.

**STOP:** не трать время на очередную кнопку CSV или ручное заполнение; это не запрос пользователя.

## Реализация (2026-11-09)

- В активной ревизии добавлены OpenFootball и OpenLigaDB автоматические источники, обнаружение данных за пять сезонов/лет, сохранённый кэш и provenance, WorkManager first-open/daily best-effort sync, источник/свежесть на главном экране и модельные купоны без выдуманных цен.
- Ручной CSV перенесён в дополнительные настройки; он не является частью стандартного сценария.
- Локальная проверка текущей ревизии: 62 unit tests и debug APK собраны. Чистый API 34 запуск синхронизировал 39 330 матчей, а офлайн-перезапуск сохранил доступ к расписанию и статусам.
- Обычный Android WebView на API 34 сохранил 8 линий Misli и 25 TOPAZ/eTopaz. Пять женских матчей УЕФА и один матч Лиги наций сверены с расписаниями. Все снимки локальные, имеют время захвата и показываются свежими до 30 минут. Право операторов на автоматическое повторное использование коэффициентов не подтверждено; ни один несопоставленный матч не получает чужой прогноз.
- Автоматическая историческая проверка на устройстве обработала 29 970 целей и выдала 19 078 прогнозов: Brier 0.6105, Log Loss 1.0234. Это ретроспектива текущих файлов с датными допущениями и без архивных версий источников, не гарантия качества будущих прогнозов.
- WebView обновляется автоматически при открытии приложения и при открытой активности; WorkManager не запускает его в фоне. OpenFootball/OpenLigaDB обновляются через WorkManager.
- Текущая ревизия ожидает собственного GitHub Actions build и APK artifact; локальные проверки успешны.
