# Research notes

**Reviewed:** 2026-11-09. This document records candidate methods, not evidence of a profitable strategy.

## Forecasting and scoring

- **Market baseline:** convert the three decimal 1X2 prices to implied probabilities, then remove overround. The app now exposes basic proportional normalization, Power, and Shin calculations. A margin-free estimate is still a market estimate; the user-entered price may not be available and the book's margin model is not known.
- **Local market-disagreement drafts:** for each exact-linked fixture with a fresh complete Misli or TOPAZ 1X2 line, compare Elo's three marginals to the proportional de-vigged probabilities. A separate virtual accumulator draft picks the largest positive difference per fixture and ranks legs by that difference. This is a descriptive research filter; the model is uncalibrated, so the draft is not a value/EV claim, and its ROI/profit-factor/drawdown outputs are suppressed. Quotes and coupons remain provider-specific.
- **International reference:** TipsAudit offers a free, no-key upcoming 1X2 API with visible attribution. It publishes a single derived fair estimate (sharp-market price after power devig where available, its model in some uncovered leagues), not independently enumerable raw Pinnacle/Betfair/bet365 lines. The Android adapter stores it outside bookmaker odds, accepts only fresh `fair_source=live` reads captured before kickoff, links exact fixtures, and uses it for descriptive probability differences only. It ignores the soft-book price/value signal, does not compute our EV, does not feed coupons, and does not create an independent market consensus. First direct capture returned 98 rows but the example Türkiye—Belgium read was ~47 minutes old, so no current reference was eligible at that check.
- **Poisson baseline:** a local feature model estimates home/away lambdas from same-competition prior goals. Team attack and concession rates are shrunk toward the league's average goals per team-match with an eight-match pseudo-count. A 1X2 score grid is built only after 50 prior league matches and five appearances per team; lambdas are bounded to 0.05–5.0. It uses goals, not external xG, and is not a probability calibrator.
- **Dixon–Coles correction:** an optional rho changes the 0–0, 0–1, 1–0, and 1–1 cells to represent low-score dependence. The comparison engine checks rho ∈ {−0.15, −0.10, −0.05, 0, 0.02} on validation Log Loss, requiring at least 100 validation forecasts; below that threshold it keeps rho at zero. The selected rho is evaluated only on the later, untouched holdout and never changes production/live forecasts.
- **Evaluation:** Brier score and log loss are implemented for an observed one-hot 1X2 result and are reported by the retrospective automatic-source walk-forward. Elo and rho selection both use the validation segment; the selected goal model and selected Elo are then compared on the same holdout fixtures where both forecast. Validation scores are used for parameter selection, not represented as unbiased performance. Coverage outside the paired sample is shown separately. These diagnostics use current source snapshots, not archived vintages, so they do not prove historical information availability or establish future accuracy.
- **Prospective ledger scoring:** the Android coupon screen reads the full saved forecast ledger for scoring while showing only a bounded recent detail list. It evaluates the latest valid pre-kickoff snapshot once per fixture and model version, and requires nonnegative score, matching outcome, named result source, and result-availability/settlement timestamps after forecast and kickoff. Repeated daily snapshots therefore do not inflate the event sample. This is a scoring-integrity improvement; it creates no new observations and is not evidence of prospective model quality until real future results settle.
- **Paired prospective market baseline:** the World Market evaluation pairs the latest retained, fresh, linked 1X2 quote for each underlying bookmaker/fixture with the newest saved current-Elo forecast already available by the quote capture time. Proportional margin removal produces the market probabilities. One bookmaker/fixture is scored once; intermediary duplicates, unlinked rows, stale quotes, post-kickoff captures, Elo forecasts made after the quote, and results without post-kickoff availability/source timestamps are excluded. Brier, log loss and top-outcome accuracy use the same settled paired fixtures for market and Elo. At 30 or more settled pairs the app reports deterministic 95% percentile-bootstrap intervals for paired Elo-minus-market score differences, using 2,000 resamples of match pairs; losses below zero favor Elo, while top-1 accuracy above zero favors Elo. The intervals assume independently sampled fixtures; repeated teams or competition rounds can make that assumption optimistic. They are withheld below 30 rows and remain descriptive. The local source history is limited to 30 days and 5,000 quote-change rows, so this is a bounded prospective diagnostic, not a permanent archive, closing-line value (CLV), ROI, or proof of market/model superiority.
- **Elo parameter experiment:** the app now evaluates a fixed grid over K={10,20,30}, home advantage={0,65,100}, and draw prior={0.22,0.25,0.28}. It partitions distinct cutoff timestamps into 60% warm-up, 20% validation and 20% final holdout; uses validation Log Loss for selection; requires at least 100 validation forecasts; and compares the selected parameters with the fixed production defaults only on holdout. Ratings remain isolated by competition and every target uses only history whose conservative availability is before its cutoff. This is one split of current source snapshots, not archived vintages, and the selected settings are diagnostic only: they do not replace the production model.
- **Expected value:** probability × decimalOdds − 1 is an algebraic conditional expectation per unit stake. It depends on a calibrated probability and an actually available price; those conditions are not established by the current prototype.

The [penaltyblog model documentation](https://penaltyblog.readthedocs.io/en/latest/models/overview.html) is a useful reference for goal models and market probabilities. It is Python software and is not embedded in Android. [Socceraction](https://github.com/ML-KULeuven/socceraction) is a research toolkit for event/action-value analysis, not a general match-result predictor or a source of licensed event data.

## Data and inference limits

- A result archive alone does not contain pre-match information timestamps. It can support retrospective form features only if each training row is cut strictly before kickoff.
- Football-Data.co.uk's [usage policy](https://football-data.co.uk/contact.php) allows private personal betting/academic use via manual download or light automation no more than twice weekly; it excludes commercial/data-training projects using heavy automated bots/scrapers/AI. One ordinary current-season `E0.csv` request on 2026-11-12 returned 100 rows through 8 Nov and zero upcoming rows with Bet365 1X2 prices. The fixture index said its latest upload was 06/11/26 11:14 UK time; the linked fixture CSV returned HTTP 429 once, so it was not retried. The site says these upcoming odds are collected Friday and Tuesday afternoons, but it does not put an individual quote timestamp in the CSV. This is not enough to treat it as a fresh current-price provider. The app still only imports a user-selected file; its first importer keeps completed FT scores and does not ingest odds. The `Date` column is treated as a source-local date with no trusted timezone; imported results are withheld until UTC midnight two days later. This conservative availability bound avoids using a same-day result at an earlier kickoff, at the cost of omitting some recent information.
- 1.ML advertises a no-key JSON odds endpoint and says to retain attribution on its [developer page](https://www.1.ml/developers), while its [Terms of Use](https://www.1.ml/terms) prohibit automated access absent express written authorization and prohibit copying/archiving content without prior written consent. Since the app requires automated collection and local price history, it is not used absent permission that covers both.
- Closing odds are a useful benchmark but can leak future market movement if treated as known earlier. Opening, snapshot, and closing prices must remain distinct.
- The app's current manual picks do not establish when a tipster first published the pick and can omit losing/deleted tips. Do not calculate a credible historical ROI from a selectively entered sample.
- Multiple accounts may copy one original prediction. Distinct names do not imply independent evidence.
- The [Blogabet study](https://alexandria.unisg.ch/entities/publication/fe6e807f-18fa-45b5-9e7b-d49d20151c3a) reports 1,534,041 picks from 3,484 tipsters and an average yield in its historical platform sample. The raw event records were not located as an open, licensed dataset. That result motivates rigorous investigation; it is not a present-day product claim.
- A separate [OddsPortal crowd study](https://ueaeprints.uea.ac.uk/id/eprint/67529/) reports 1.317% average returns from a majority-prediction strategy across 68,339 events. It is a historical research result, not an independently reproduced estimate for this application.
- Average crowd consensus may simply restate the market or share common information. Any crowd contribution must be compared to a timestamp-matched, de-vigged market baseline on future data.

## International bookmaker odds (reviewed 2026-11-12)

- Rechecked the requested public pages and official terms on 2026-11-12. Oddsbunch showed named-book 1X2 prices with relative ages, but not exact quote timestamps; its Terms §8 prohibit automated scraping/excess requests and §9 require permission for reproduction beyond personal viewing. BetExplorer's odds-filter route presents an age confirmation gate, while its terms prohibit automated requests and embedding, aggregating, scraping or recreating content without express consent; the gate was not accepted or bypassed. Oddspedia displayed upcoming 1X2 prices without a verified per-price timestamp or clear underlying-book label, and its public terms prohibit reproduction without prior written consent. Oddspedia advertises free feeds/widgets, but account creation requires legal name and verified email, can require manual activation, and the usage agreement restricts service to owned/controlled online assets and prohibits third-party redistribution; widgets are domain-bound. OddsPortal's Livesport terms prohibit automated requests and aggregation/scraping without express consent. The reviewed Oddschecker `/us` terms direct that product to named US states/Ontario, require written consent for reproduction/storage, and reserve blocking automated activity and restricting jurisdictions. No adapter was added. Android WebView behavior, JavaScript internals, hidden routes, and Azerbaijan-device access were not tested because the permission or account/region gate failed or remained unverified.
- MoviOdds documents a no-key soccer JSON endpoint filtered to prematch group 40 (Full Time Result). Its terms permit use in one's own app, prohibit attempts to bypass limits/security, and say the feed is independent and not affiliated with bet365. The app labels the origin “bet365 via MoviOdds,” not as a first-party API. This provider-level reuse permission is not a bet365 endorsement or guarantee. The terms require users to be 18+.
- The [Odds Gap API documentation](https://theoddsgap.com/api-docs) advertises free no-key JSON and personal/AI-assistant use with attribution, but explicitly says its endpoints are intended for reading its board and not as a data source for other products; repackaging its feed inside an app is prohibited. The [UK Odds API free tier](https://docs.ukoddsapi.com/getting-started/plans-and-pricing) requires account/key setup, offers 300 requests/month and only two UK books, so it was not added. The user authorized a free account for [The Odds API](https://the-odds-api.com/); its official terms permit mobile-app display/storage and derivatives, while prohibiting raw-feed resale and requiring a private key. It is integrated in a local personal build; the public CI APK remains keyless.
- The latest international provider response now records a mutually exclusive parser breakdown: accepted, rejected, stale, duplicate, and unverified event rows. A malformed/inaccessible response has no invented parse counts. These counts describe one request only; they are not a reliability percentage or accuracy estimate.
- MoviOdds requires a one-time provider-specific age 18+ confirmation. The user explicitly confirmed it; the local personal build stores the confirmation, and the Worker checks it before fetching. Football data, TipsAudit and The Odds API are not gated by this setting.
- A direct GET at 2026-11-12 00:39:24 UTC returned 923 fixture rows and 2,712 1X2 selections. The app-equivalent quality gate retained 904 future, prematch, fresh, complete and unsuspended lines. The example Club America (W)—Toluca (W) line was 1.20/7.00/8.50; its draw price last changed at 00:09:08 UTC, while group 40 was re-read at 00:39:24 UTC. Price `ts` and successful poll time are different facts.
- Source-poll freshness is 15 minutes; device/server clock skew above 5 minutes is `UNVERIFIED`; `group_status["40"].stale=true` or old `polled_at` is `STALE`; blocked HTTP access is `BLOCKED`; request/parser failures are `ERROR`; no valid future rows is `UNAVAILABLE`. The app stores per-outcome source `ts`, provider `polled_at`, and app `captured_at` independently. Stable prices can have an old `ts` when the provider has recently reread the market, so freshness uses `polled_at` rather than rejecting solely on the price-change time.
- Current MoviOdds quote state is updated each fetch; a 30-day history row is appended only when a price or its source change timestamp changes. This supports offline inspection and line movement without storing repeated unchanged boards. The international engine counts each underlying bookmaker once per exact normalized event across all source providers. The Odds API can supply multiple named books, but this does not establish an independent predictive edge.
- Proportional margin removal is descriptive. Differences from Elo, Misli or TOPAZ do not constitute EV or a value bet. No EV is emitted until there are verified local prices and the model has prospective evaluation; international prices cannot enter a local operator's virtual coupon. The feed has not been tested on a physical handset in Azerbaijan; regional availability and exact local fixture coverage remain unverified.

#### The Odds API V4 proof and Android integration (2026-11-12)

- A real documented API call at `2026-11-12T08:36:31Z` found 45 active soccer competitions. The EPL odds response had 20 upcoming events and 298 complete fresh bookmaker 1X2 lines; the API charged one credit and returned 499 remaining. The observed Man City—Fulham event at 12:30 UTC on 21 Nov had an update age of about 10 seconds. These numbers/quotes are historical POC evidence only; do not display them as current. The match did not link to the local database because OpenFootball supplied only a date and OpenLigaDB did not have the fixture at the exact kickoff.
- A follow-up documented EPL request at `2026-11-12T10:07:21Z` authenticated successfully, returned 20 events / 298 complete lines, cost one credit and showed 498/500 remaining. This validates the configured account key and endpoint at that time, not the Android Worker's database matching or regional phone access.
- A later session check accepted the configured local credential: `/v4/sports/` returned HTTP 200, 46 in-season soccer catalogs and zero quota cost. One EPL EU h2h request then returned 20 future events and 298 complete 1X2 lines; sampled source updates were 14:37:17–14:37:54 UTC and the response reported 3 credits used / 497 remaining. These raw POC rows were not imported; no current quote or Android Worker/Azerbaijan test is claimed.
- `TheOddsApiProvider` validates documented V4 h2h fields, server `Date` versus device clock, market update timestamps, prematch kickoff, full decimal 1X2, duplicate events and unique local linking. SQLite records whether a link used exact kickoff or a unique same-UTC-date local fixture. It stores the source poll and local capture separately. It does not infer book prices or transform Odds API quotes into Misli/TOPAZ lines.
- `TheOddsApiOddsWorker` is enabled only by a personal local APK build. It fetches the active soccer catalog, caches it for seven days, requests one rotating league per two-hour pass, caps attempts at 12 per rolling 24 hours, honors `Retry-After`, and persists quota headers. If the last reported balance is 20 credits or less, it pauses until after the first UTC day of the following month. The [official FAQ](https://the-odds-api.com/manage/faqs.html) says credits reset on the first of every month. The [official usage docs](https://the-odds-api.com/liveapi/guides/v4/) charge one credit per market and region (one h2h market in EU costs one); the observed free plan is 500 monthly credits. The provider lists 1X2 pre-match refresh at 60 seconds, with intervals tightening during the six hours before kickoff, while our parser requires the market timestamp to be within 15 minutes of the trusted response date ([update intervals](https://the-odds-api.com/sports-odds-data/update-intervals.html)). Spreading up to 12 calls across the day increases the chance of opening the app during a fresh capture window without spending more monthly credits. The active catalog rotates over multiple days (46 competitions in the latest host check) and WorkManager is best-effort; the app falls back to cached local data offline.
- The API key is read from ignored `local.properties`; it is deliberately absent from GitHub Actions variables and uploaded artifacts. The `personal` APK embeds that key, is signed with the local debug key, and must remain private. CI builds the variant keyless only to catch build errors; it uploads only the separate keyless debug APK. A physical Azerbaijan-device run is still pending.

## Experimental policy

Before any strategy is promoted:

1. Freeze a dated dataset and record data licenses and capture timestamps.
2. Split training/validation/test by time and use walk-forward evaluation.
3. Compare against market-implied probability and simple Poisson/Elo baselines.
4. Report calibration, Brier, log loss, ROI, CLV, drawdown, sample count, uncertainty intervals, and stake assumptions.
5. Keep tuning out of the final test window; publish failures and versions in the experiment log.

The TipsAudit derived-reference ledger is not a historical odds archive: each saved fair-market snapshot expires from comparisons after 30 minutes, and its POC returned no fresh row. MoviOdds is now a separate named-bookmaker source, but its captured board is time-bound and does not create a prospective accuracy sample or deep market history. A market-baseline evaluation needs timestamped future coverage and a separate held-out interval; comparisons remain descriptive.

The user-imported CSV walk-forward is a separate Elo evaluator; no real historical file has been run through it in this workspace, and that CSV-specific report does not pair its results to a market baseline. The app has only a bounded prospective odds/forecast pair report, not full-coverage timestamped odds or a licensed tipster dataset.
