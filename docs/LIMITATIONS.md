# Current limitations

The app is an offline-first research notebook with experimental probabilities, not a validated betting product.

- Two international sources are integrated and remain distinct: bet365 via independent MoviOdds, plus The Odds API V4 bookmaker aggregator (EU). The user confirmed age 18+ for MoviOdds; its provider-specific gate is enabled only in the local personal build. The Odds API key is read only from ignored local `local.properties`; it is not committed or included in CI APK artifacts. A personal APK embeds the key and must remain private. At the historical The Odds API POC (2026-11-12 08:36 UTC), the catalog had 45 soccer leagues and the EPL response contained 20 events/298 complete fresh lines, using 1/500 credits; a follow-up authenticated request at 10:07 UTC cost one credit and left 498/500. All observed quotes have expired. At the separate MoviOdds POC (00:39 UTC), 904/923 returned events passed prematch/source-poll 1X2 checks; those quotes have expired too. The user has no confirmed physical-device access from Azerbaijan. The free The Odds API cadence is bounded to 12 rotating leagues per 24-hour batch while quote freshness is 15 minutes, so it cannot keep every league continuously fresh. International lines may form a named multi-book reference only when distinct fresh book lines refer to the same unique local fixture; this is descriptive, not a validated consensus advantage or EV. Neither international provider feeds Misli/TOPAZ coupons. Oddsbunch, BetExplorer, Oddspedia, OddsPortal and Oddschecker remain unintegrated due reuse permission or regional-access constraints. See [DATA_SOURCES.md](DATA_SOURCES.md).
- The international screen shows the latest parser's accepted/rejected/stale/duplicate/unverified counts and five recent attempts from a 30-day local ledger. Failed requests have no parse counts. This is observed history, not a statistically estimated reliability score; the dataset is too short to measure stable uptime or accuracy.
- The Odds API endpoint is a real feed, but its daily rotating credit budget means it is not a continuous live board. Football-Data.co.uk permits light personal-use automation, but the inspected current season file had no future quoted rows and no quote-level timestamp; its fixture CSV returned HTTP 429 once and was not retried. 1.ML's public developer page conflicts with terms requiring express written authorization for automated access and prior written consent for copying/archiving. Neither source is integrated as an additional live line.

- OpenFootball and OpenLigaDB sync are implemented with local persistence, provider timestamps, retry/backoff, cache and duplicate suppression. A separate clean API 34 first-run completed across five OpenFootball seasons and five OpenLigaDB year catalogs: 38,609 merged matches, 29,612 completed results, 183 competition labels and 120 prospective forecasts. The active signed APK update-installed without clearing data and retained `firstInstallTime`. Another API 34 database contains 39,181 merged rows across 184 competitions. The `e8c3a33` continuation fix passed CI and was tested on Android 8/API 26: both providers reached `OK`, and the continuation completed without exponential backoff. A later stable-signed API 26 update migrated v10→v11 and exposed writer/writer contention between sync and foreground forecast persistence. Commit `6425117` serializes `Store` mutations; Actions [42912446156](https://github.com/jafarovsamir89/Football-Intelligence/actions/runs/42912446156) passed 88 JVM + 12 API 34 tests and built the stable-signed APK. Its API 26 update-install preserved `firstInstallTime`; after forcing the app-open freshness path, both real providers completed `OK` while the Activity remained active, with 38,609 matches / 29,612 results retained and no SQLite lock or fatal crash. No physical-device football data-sync run is recorded.
- OpenLigaDB is community-maintained. The app discovers football competitions for five calendar-year catalogs. Each Worker reserves up to three minutes for OpenFootball and allows OpenLigaDB to continue until the seven-minute total source deadline, then queues remaining history. WorkManager is best-effort and Android may defer work.
- OpenFootball rows without exact kickoff time are shown as date-only and cannot generate a kickoff-based forecast. International odds may link such a row only when exact normalized home/away order and UTC date identify exactly one unfinished fixture; the UI records that the link is date-only, not exact kickoff. Multiple same-day candidates stay unmatched. Local bookmaker quotes still require exact kickoff matching. Historical results are held until the conservative availability date.
- Cross-feed deduplication is intentionally strict: same event date, normalized team names, and same home/away order. If names do not normalize exactly or multiple same-day candidate fixtures exist, both records remain rather than guessing.
- Latest API 34 public-page checks at 2026-11-10 21:34:53 UTC (Misli) and 21:35:11 UTC (eTopaz) returned zero verifiable future prematch 1X2 lines and were recorded as `UNAVAILABLE`. The previous 21:04–21:05 capture had 9 Misli lines (0 exact local links) and 25 TOPAZ lines (7 exact links); Portugal—Denmark / match 85257 had 1.47/4.24/5.14 then. Those prices expired and are not current. The updated foreground collectors coalesce duplicate page callbacks and schedule a refresh at the 30-minute boundary; this latest run stayed stable without a repeated capture, crash or SQLite lock. An isolated API 34 test emulator has no default network and its `chromewebdata` output is an offline harness condition. No hidden endpoint or evasion fallback is used. Explicit automated odds-reuse permission remains unconfirmed; snapshots stay on-device. WebView capture runs in foreground, not through WorkManager.
- TipsAudit is integrated only as a *derived market reference*, not as a bookmaker. The live POC returned 98 records at 2026-11-11 23:22 UTC, but its Türkiye—Belgium fair read was ~47 minutes old and therefore rejected by the app's 30-minute rule. The current capture supplied no eligible comparison row. The app ignores that service's soft prices/value flags and uses no TipsAudit value as an operator payout, EV input or coupon price. Any comparison is single-feed descriptive probability difference, not independent consensus. Pinnacle API access is inquiry/variable-cost, Betfair live API requires credentials and a £499 activation fee, and bet365 terms restrict automated extraction; those providers have no verified free/no-key adapter.
- The app builds same-bookmaker price-backed virtual accumulators when every leg has a fresh exact fixture match. At the historical capture Misli had no exact local fixture links, so no Misli price-backed coupon was created; TOPAZ generated separate candidates from actual source prices, which expire from fresh use after 30 minutes. Model-only drafts remain available without prices. Joint probability uses Fréchet lower/upper bounds; no independence model or real payout claim exists. A coupon is marked lost after any incorrect finished leg, even if others are pending. ROI, profit factor and drawdown are withheld whenever any settled coupon in the evaluated group has no full combined price; the UI reports price coverage separately. No prospective profitability has been established.
- A separate local market-disagreement draft compares Elo marginals with de-vigged probabilities from the same exact-linked, fresh complete Misli or TOPAZ 1X2 line. It stores each selected fair probability and difference. This is descriptive only: Elo is uncalibrated, no EV/ROI/profit metric is displayed for this basis, and these selections do not prove an edge.
- The local DB includes 566 legacy placeholder-team rows. They are retained for migration safety but hidden from normal results and excluded from forecasts, picks, fixture linking, accumulators and walk-forward; parser/upsert paths reject new placeholders. Post-filter automatic-source walk-forward: 29,588 targets, 19,185 forecasts, 10,403 insufficient-history skips, Brier 0.6106, Log Loss 1.0235. This is still retrospective and uncalibrated.
- Automatic coupon drafts select the top available Elo marginal per eligible fixture. This is not a value filter or validated recommendation. No probability calibration, independent forward test, stake sizing, or dependence/correlation model exists. Accumulator outcomes are checked against saved local results; a kickoff move above 30 minutes is marked for review instead of treated as a loss.
- The walk-forward screen reports retrospective one-vs-rest ECE and reliability bins by outcome. The app does not apply a calibration transform, and the values rely on current source snapshots rather than archived vintages or prospectively frozen forecasts.
- The v11 prospective journal is CI- and API 34 update-install-verified. The last documented data-bearing install (2026-11-10) had 62 immutable future snapshots and 0 settled results; no prospective accuracy estimate was available then. The evaluator now reads the full local ledger, selects one latest pre-kickoff forecast per fixture/model version, and validates the stored score, result source and post-kickoff availability time. No new results were gathered or database was installed during that code change. No market baseline, CLV, confidence interval, calibration guarantee, or profit evaluation exists.
- Elo uses production defaults and requires at least 10 prior same-league matches and 3 appearances per team. A separate 27-setting K/home-advantage/draw-prior grid is selected on a chronological validation segment and then evaluated on a final holdout; it requires at least 100 validation forecasts and does not change live settings. The Poisson baseline estimates goal rates from goals scored/conceded, not external expected-goals data; it requires 50 league matches and 5 team appearances. Dixon–Coles rho is selected from a five-value grid on validation Log Loss only when at least 100 validation forecasts exist; otherwise rho stays at zero. The paired holdout excludes fixtures where either model lacks a forecast. Validation is a tuning set, while only the final holdout is used for the comparison; both are one retrospective split of current files rather than archived vintages and may reflect snapshot-selection bias. Probabilities remain uncalibrated and these models do not establish advantage.
- CSV walk-forward remains optional in Settings → Additional. The app also runs a walk-forward over automatic-source results; its source-availability assumptions and lack of archived versions limit historical interpretation.
- The app does not import crowd/tipster picks. No free permitted automated tipster feed was confirmed.
- The previous manual quote/ticket database is preserved for upgrades, but manual quote entry is not part of the current main user flow. No real bet or bookmaker account action exists.
- GitHub Actions builds a debug APK signed with the debug key. Release signing and Play Store distribution are not configured.
