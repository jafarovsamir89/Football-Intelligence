# Architecture

## Current implementation (native Android, local-first)

```text
MainActivity host → FootballScreen / Compose
  ├── WorkManager schedulers (football first-open/24h + fair-reference and international-odds first-open/periodic, network constrained; MoviOdds waits for 18+ confirmation)
  │     └── AutomaticFootballSyncWorker (network constraint, unique lock, retry/backoff)
  │            ├── OpenFootballSync → GitHub directory discovery + public raw CC0 JSON
  │            └── OpenLigaDbSync → official API catalog, matches, group/change polling
  │     └── TipsAuditMarketReferenceWorker → public fair-odds JSON, strict freshness parser
  │     └── InternationalOddsMarketWorker → documented MoviOdds group-40 soccer 1X2 feed, source-poll quality gate
  ├── Misli and TOPAZ public-page WebViews (foreground, visible DOM only, gated capture/reload at 30-minute freshness)
  ├── Store.kt / SQLite v16 with WAL (matches, separate local/international bookmaker and derived-market ledgers, forecasts/history)
  ├── EloEngine → exact-kickoff forecasts with safe-availability cutoff
  └── VirtualCouponBuilder → separate model-ranked and same-bookmaker fresh-price accumulator drafts
```

No server, account, secret, paid API, or bookmaker action exists. WorkManager runs best-effort; Android controls exact scheduling. Public source rows and HTTP metadata are persisted for offline use. CSV remains an optional Settings feature.

### Compose and SQLite reads

`FootballScreenStoreSnapshot.kt` groups the Compose screen's SQLite reads into an immutable read model fetched on `Dispatchers.IO`. `FootballScreenRepository` is the screen-facing persistence boundary for that read model, fixture history, bookmaker captures, forecast/coupon writes, CSV import, and backtest data. Its SQLite adapter confines operations to `Dispatchers.IO`; WorkManager and migration tests may still use `Store` directly. Both public bookmaker WebViews parse and persist within the Compose lifecycle coroutine scope, so destroying the screen cancels pending work. Parsing remains on `Dispatchers.Default`. The screen retains its last successful data if a later read fails and surfaces that failure in the source-status area. The first bookmaker WebView capture waits for the stored last-check time so asynchronous screen loading preserves the existing freshness gate. This boundary does not change SQLite schema or migration behavior.

### Persistence technology decision

Do not migrate to Room in the current milestone. The demonstrated UI problem was synchronous screen access, which is now behind a repository and moved to `Dispatchers.IO`; no Room-specific failure remains. `Store.kt` owns a version-16 schema with migrations from older installs and user-owned match, quote, coupon, import, and forecast data, and its isolated migration suite checks preservation across the supported upgrades. Replacing it would add entity/DAO conversion and another migration implementation without solving a measured requirement. Reconsider Room if a concrete invalidation/query-maintenance need appears or SQLite defects continue despite WAL and serialized writes. Any future migration must first copy and verify a data-bearing v16 database, preserve all history/IDs, and prove rollback/reopen behavior on API 26 and 34.

## Provider and persistence rules

- `ProviderMatch` keeps stable provider ID, competition/season, event date, exact-vs-date-only kickoff, source URL, capture time, and safe result-availability time.
- `OpenFootballJsonParser` consumes repository catalog JSON and match files. Paths are validated; duplicate rows within a file are removed; missing competition files remain absent instead of being invented. A date-only fixture never gets an estimated kickoff.
- `OpenLigaDbParser` discovers only football leagues, accepts final-result type records, and parses explicit UTC kickoff. Requests are spaced 1.25 seconds apart (48/min), under the published 60/minute limit. Current-year leagues use current group and last-change checks; older catalogs refresh weekly. Each Worker reserves up to three minutes for OpenFootball, then lets OpenLigaDB use the remaining window under a seven-minute total source deadline. It appends a continuation to the unique one-time WorkManager chain and succeeds so Android does not apply exponential retry backoff to normal progress. `APPEND_OR_REPLACE` starts a clean chain after any failed/cancelled prerequisite. On HTTP 429/503 the affected provider stops its remaining catalog/file requests immediately. A valid `Retry-After` delta-seconds or RFC 1123 date schedules one network-constrained delayed retry at the longest supplied delay across both providers; missing or invalid headers and other provider/network failures use WorkManager's exponential retry.
- SQLite upserts are stable by provider source key. An incomplete observation cannot erase a stored score. Cross-provider merging requires one strict same-date, same-home/away normalized candidate; if there are zero or multiple candidates, the app does not guess. A more precise kickoff/result can upgrade the existing row while preserving source URLs and combining source labels.
- Store enables SQLite WAL so foreground reads can use the last committed snapshot while WorkManager writes a provider batch. The foreground does not launch a duplicate unmatched-quote relink at startup; the Worker relinks after each provider sync segment. An API 34 instrumentation test covers reader visibility during an open provider write transaction.
- Each model pick and accumulator is saved before kickoff. Accumulators use supported sizes 2/3/5/8/10 and rank eligible legs by model marginal. Separate same-book drafts require a complete fresh quote for every fixture; the research-only market-disagreement basis selects only positive model-minus-de-vigged probabilities and keeps the selected fair market probability/delta per leg. Those drafts require exact local fixture IDs and never show EV/ROI. Prices are never mixed. Identical strategy/price/outcome sets are not duplicated in history, while the quote table independently preserves observed timestamps.
- A full same-provider price product may be displayed as combined decimal odds. Since cross-match dependence is not modeled, joint model probability is shown only as Fréchet bounds (`max(0, sum(p)-n+1)` to `min(p)`). Conditional EV is only an experimental interval for non-disagreement drafts when every price exists; it is not a profit estimate. Settlement marks a coupon LOST as soon as any finished leg is incorrect, even while other legs are pending; schedule changes over 30 minutes remain a review state. ROI, profit factor and drawdown require complete price coverage and remain disabled for market-disagreement research drafts. The UI separately reports priced count and coverage.
- `TeamDataQuality` rejects known placeholder identities and same-team fixtures. Legacy rows remain in SQLite for ID/migration safety, but reads, fixture matching, models, and evaluations exclude them; parser and write paths prevent new placeholder rows.
- `MisliOddsProvider` parses only complete 1/X/2 rows from the visible `document.body.innerText` of the public `/idman-novleri/futbol` route. It requires a future event, visible date/time, device timezone, valid prices, and exact reviewed team aliases. It links an event to local history only for one exact date/home/away/kickoff match. Each quote snapshot retains its raw names, source URL, time, market and capture timestamp; UI freshness expires after 30 minutes. The WebView is loaded on app open and while foreground; WorkManager does not run this browser collector.
- `TopazOddsProvider` reads visible text from eTopaz's normal public sports tab, requires complete future 1X2 rows, and marks its inferred year. Neither provider has bypass or login logic; live observations are rejected.
- `TipsAuditFairOddsProvider` reads a separate public, no-key JSON endpoint that requires visible attribution. It accepts only `fair_source=live`, source-read time before capture and kickoff, <=30-minute freshness, coherent 1X2 fair probabilities/reciprocal prices and an HTTPS TipsAudit event URL. A strict unique exact team/order/UTC-date/kickoff match may attach a local fixture ID. SQLite stores provenance and methodology in `market_reference_snapshots`, never in `bookmaker_odds_snapshots`; an independent Worker checks when app-open data is older than 15 minutes and runs a 30-minute best-effort periodic request. Its prices are not local bookmaker quotes, coupon prices or EV inputs. TipsAudit and MoviOdds workers also honor valid HTTP 429/503 `Retry-After` headers by queuing their own delayed network-constrained work.
- `Bet365ViaMoviOddsProvider` consumes only the documented, keyless `GET /odds?sport=soccer&groups=40` response. It accepts group 40 only, requires one unsuspended home/draw/away quote, a future prematch fixture, valid decimal prices, explicit market `polled_at`, non-stale status, and source/device clocks within five minutes. The maximum source-poll age is 15 minutes; `ts` for each selection is preserved separately and may be old while a stable line is freshly confirmed. Missing poll metadata is `UNVERIFIED`; HTTP refusal is `BLOCKED`; errors are never promoted to fresh prices. Both scheduling and Worker execution require a locally stored 18+ confirmation from the user, matching MoviOdds terms; football and TipsAudit sync are not gated.
- SQLite v16 keeps the latest parser counts for received, accepted, rejected, stale, duplicate and unverified events plus a 30-day append-only attempt ledger. The World Market shows five recent statuses and counts; HTTP failures and responses with no parseable JSON keep counts null. This is an audit trail, not an uptime/reliability estimate.
- The MoviOdds field and book attribution are separate: `provider_id=moviodds_bet365`, `bookmaker_id=bet365`, visible text says “bet365 via MoviOdds.” The provider's terms permit use in one's own app but say MoviOdds is independent and unaffiliated with bet365; this is not a bet365 license or endorsement. Physical access from Azerbaijan is not verified. SQLite `international_odds_current` stores the latest source-confirmed line; `international_odds_snapshots` appends only price or source-`ts` changes (30-day retention), so routine unchanged polls do not inflate the history. Current data expires after 15 minutes without a provider poll.
- The international market engine removes each bookmaker's margin using proportional normalization, then averages only distinct bookmaker identities for an event. Event grouping requires complete-link identity: every row in a group must match exact normalized home/away order within a five-minute kickoff tolerance, and conflicting non-null local match IDs cannot merge. A row that could match two groups is left separate instead of guessed into either; this prevents transitive timing chains from combining adjacent fixtures. One current bookmaker is labelled a one-book reference, not a market consensus. Local Misli and TOPAZ quotes remain separate, and international quotes never enter their virtual coupon builder.
- `ForegroundBookmakerCaptureGate` coalesces repeated `onPageFinished` notifications and permits one capture per 30-minute interval. If a fresh quote state is present on app open, a delayed foreground WebView load starts at the freshness boundary; one delayed reload follows each completed attempt. This does not run in WorkManager or when the app is not open.
- After commit `01706e9` passed Actions [42895248921](https://github.com/jafarovsamir89/Football-Intelligence/actions/runs/42895248921), its stable-signed APK update-installed over the data-bearing API 34 app and captured 9 Misli visible lines/0 exact local links and 25 TOPAZ/7 exact links at 20:33 UTC without another SQLite lock. Portugal—Denmark / local match 85257 had TOPAZ H/D/A 1.47/4.24/5.14. Those prices expire after 30 minutes. Misli robots and reviewed eTopaz terms do not establish explicit odds-reuse permission. The app stores snapshots locally; `LIVE` means technical capture, not legal authorization, continued availability or profitability.
- The local Elo walk-forward is computed per competition using strict saved availability cutoffs. It runs in a background thread from the Backtest tab. Date-only OpenFootball targets use a date boundary, scored results are considered available two days later, and later-captured OpenLigaDB results cannot enter earlier training. Source files are current snapshots rather than archived historical vintages, so its metrics are retrospective research, not proof of reliable future probabilities.
- `CalibrationDiagnostics` computes equal-width one-vs-rest reliability bins from walk-forward predictions and observed outcomes. The Backtest screen shows the macro mean calibration gap, per-outcome counts/ECE, and occupied-bin predicted-vs-observed frequencies. This is descriptive retrospective diagnostics; it neither fits a calibrator nor establishes prospective accuracy.
- `EloParameterExperimentEngine` splits distinct forecast cutoff timestamps chronologically into 60% rating warm-up, 20% parameter validation and 20% final holdout. It scores a fixed 27-configuration grid by validation Log Loss, requires at least 100 validation forecasts before selecting, and only then evaluates the selected configuration on the untouched holdout beside the production defaults. It resets ratings per competition and keeps each prediction's strict availability cutoff. The screen labels this a single retrospective experiment on current source snapshots; it never changes model parameters or saved forecasts automatically.

## Forecasting

`EloEngine.kt` fits same-league results whose safe availability time is strictly before the forecast cutoff. It uses initial rating 1500, K=20, home advantage +65, and a 25% draw prior weighted as four matches. Forecast display requires 10 league matches and 3 games per team. These defaults are transparent, not fitted or calibrated. The UI excludes date-only upcoming rows from kickoff-based forecasts.

`EloWalkForwardEngine.kt` and the automatic-source evaluator apply conservative `available_at` bounds. Legacy placeholder fixtures are excluded. Current source files are not archived vintages, so retrospective scores cannot establish historical real-time knowledge.

`ProbabilityEngine.kt` contains 1X2 de-vigging and Poisson/Dixon–Coles score-grid mathematics. `GoalExpectationEngine.kt` estimates home/away goal lambdas from prior same-competition goals, with an eight-match prior toward the league average, minimum league/team sample gates, bounded lambdas and strict availability-before-cutoff updates. `GoalExpectationWalkForwardEngine` batches equal effective-availability times and rejects source timestamps earlier than kickoff rather than guessing when the result became usable. Elo and Poisson share this guard. A small fixed Dixon–Coles rho grid is selected by validation Log Loss only after at least 100 validation forecasts; otherwise rho stays at zero. The selected rho is then evaluated on the untouched chronological holdout beside validation-selected Elo, on fixtures forecastable by both, while wider model coverage is reported separately. Validation scores are selection data, not an unbiased performance estimate. The model remains retrospective, uses goals rather than external xG, and does not alter live or saved Elo forecasts. TipsAudit remains a derived fair-market reference; MoviOdds can provide a named-bookmaker comparison when a fresh exact-linked line exists. Neither supplies prospective validation or a claim of betting advantage.
