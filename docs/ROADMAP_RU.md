# Football Intelligence — дорожная карта Android

## Цель

Личное Android-приложение с нулевой стоимостью и нулевым обязательным вводом: автоматически получает разрешённые футбольные расписания и результаты, хранит их локально, строит честные вероятности и сверяет сохранённые виртуальные прогнозы. Реальных ставок, аккаунтов и платных API нет.

## Что реализовано в активной ревизии

- OpenFootball football.json: обнаружение JSON-файлов в пяти европейских сезонах и всех доступных в каталоге соревнованиях; CC0-наборы, ETag, ежедневная проверка текущего сезона, ежемесячная проверка старых данных, безопасные date-only записи.
- OpenLigaDB: динамическое обнаружение футбольных лиг за пять календарных лет, полный исторический импорт с лимитом 48 запросов/мин, локальное кэширование, проверка текущей группы/last-change, недельное полное обновление, bounded Worker + retry.
- WorkManager: уникальная периодическая задача раз в 24 часа и задача при запуске, если последний успех устарел на 8 часов. Android может отложить задачу; приложение сразу открывается с локальной базой.
- SQLite: provenance, источник и capture/availability timestamps, сохранение ранее полученных результатов, conservative dedupe по дате и нормализованным домашней/гостевой командам; миграция версии 8 хранит bookmaker snapshots, статусы и признак выведенного года.
- Главный экран: синхронизация и свежесть источников, матчи, отдельная история результатов, автоматический Elo для точных предматчевых kickoff, виртуальные model-only черновики для двух операторов и журнал их исходов.
- MisliOddsProvider и TopazOddsProvider автоматически читают только видимый текст обычного публичного Android WebView. На API 34 зафиксированы 8 линий Misli и 25 линий eTopaz с реальными 1/X/2 значениями и временем захвата. Модель сравнивается только при точном совпадении команды/даты/kickoff; в проверенной выборке таких сопоставлений не было. Свежесть ограничена 30 минутами. Условия автоматического повторного использования котировок обоими операторами остаются неясными.
- eTopaz не указывает год события; парсер принимает следующий календарный occurrence лишь в пределах 90 дней и явно отмечает выведенный год. Türkiye–Belgium cross-check по времени прошёл через расписание Лиги наций УЕФА.
- Финальный API 34 first-run sync завершился через WorkManager retries: 39 181 объединённый матч, 30 090 завершённых счётов, 184 соревнования; OpenFootball 25 904 / OpenLigaDB 17 776, оба `OK`. Walk-forward на этой базе: 30 090 целей, 19 185 прогнозов, Brier 0.6106 и Log Loss 1.0235. Это оценка текущего набора без архивных версий источников, не подтверждение будущего качества или прибыли.
- CSV-импорт доступен только в настройках и не нужен основному сценарию. Walk-forward по CSV остаётся дополнительным; основной отчёт использует локальную автоматическую историю.

## Проверки текущей ревизии

- API 34 fresh install: full provider sync завершён, UI показывает обе котировочные платформы и свежесть, переход на офлайн сохранил расписание/статусы.
- 62 unit-теста прошли локально и в GitHub Actions. Последний artifact run [42731992205](https://github.com/jafarovsamir89/Football-Intelligence/actions/runs/42731992205) прошёл тесты, сборку, стабильную подпись и загрузку; update install на API 34 сохранил SQLite.
- Проверка конкретных купонов показала реальные числа операторов, но все 33 котировочных события остались без локального match ID и без модельного сравнения.

## Оставшиеся инженерные задачи

1. Проверить repeatable update signature для APK из двух последовательных GitHub Actions runs.
2. Добавить DB/WorkManager instrumentation для миграций, сетевых повторов и offline-cache; проверить API 26 и физический телефон.
3. Уточнить условия автоматического локального использования цен Misli/eTopaz; не обходить ограничения страниц и не заявлять право на данных без подтверждения.
4. Улучшить покрытие точного сопоставления операторских событий с локальными календарями, сохраняя отдельные unmatched котировки.
5. Собирать будущие snapshots прогнозов и результатов по мере завершения матчей; только после независимого времени проверки обсуждать калибровку и market baseline.

## Далее

- Подключить автоматические результаты к хронологическому walk-forward; хранить неизменяемые forecast snapshots, versioned inputs, Brier/Log Loss и calibration diagnostics.
- Построить форму команд и Poisson/Dixon–Coles на достаточной истории только после валидации временного среза.
- Добавить Room/DAO + repository/ViewModel без потери пользовательской SQLite, резервное копирование и тесты API 26.
- Добавлять рынки только с независимой схемой рынка, точной стороной, source URL и timestamp.
- Вернуться к bookmaker-specific EV только после получения свежих, проверенных odds, сопоставленных по одному оператору; не сравнивать или смешивать коэффициенты операторов в одном купоне.

## Утверждения о качестве

Не показывать доходность/преимущество, пока прогнозы не заморожены заранее и не проверены на независимом временном диапазоне против timestamped market baseline. Не выдавать максимальную вероятность за вероятность выиграть весь купон.
