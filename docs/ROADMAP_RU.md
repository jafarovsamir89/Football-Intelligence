# Football Intelligence — архитектура и дорожная карта (Android, 0 ₼)

## Цель и ограничения
Личное Android APK-приложение для исследовательской проверки футбольных рынков и записи только виртуальных ставок. Без платных API, подписки, сервера и обязательной регистрации. Пользовательские данные хранятся на устройстве.

## Статус этапа A: локальная лаборатория (частично реализовано)
- Нативный Kotlin / Compose, Android SDK 35, minSdk 26.
- OpenLigaDB: HTTPS API для выбранных лиг/сезонов; загрузка запускается пользователем.
- SQLite для матчей, 1X2-снимков, прогнозов и виртуальных одиночных ставок.
- Basic/Power/Shin удаление маржи, простое среднее свежих введённых линий и расчёт ROI только по рассчитанным виртуальным ставкам.
- Математические примитивы независимого Poisson и Dixon–Coles с unit-тестами. Параметры моделей ещё не оцениваются на исторических данных; прогноз матча не показывается.
- Ошибки источника отображаются, сохранённые данные доступны офлайн.
- GitHub Actions run 42705882847 прошёл unit tests, собрал APK и загрузил artifact football-intelligence-debug-apk для ревизии 3372f23.
- Workflow использует checkout v7, setup-java v6, setup-gradle v6, upload-artifact v7 и Ubuntu 24.04. CI выдал advisory, что Gradle 8.11.1 устарел; совместимость AGP/Gradle записана в TESTING.md.

## Этап B: данные и импорт
- Каталог лиг и сезонов OpenLigaDB вместо жёстко заданных кнопок.
- CSV/JSON импорт через Android Storage Access Framework.
- Отдельные provider ID и canonical match ID, source captured time и ingest time.
- Дедупликация, проверка рынка, UTC-нормализация, лимиты и контролируемые повторные попытки.
- Ручной импорт исторических файлов только при проверенных условиях использования.
- Не использовать закрытые endpoint, токены сторонних приложений, обход авторизации/CAPTCHA или запрещённое автоматическое копирование.
- Нет данных — пустой результат с причиной, без фиктивных матчей/котировок.

## Этап C: проверяемая статистика
- Хранение независимых снимков по конкретному рынку; не объединять 1X2, Double Chance, DNB, Asian Handicap, Totals и BTTS.
- Зафиксированные по времени рыночные baseline, opening/snapshot/closing odds и проверка будущих данных.
- Вероятности market, Elo и Poisson/Dixon–Coles с параметрами, обученными только на информации до прогноза.
- Метрики Brier, log loss, ROI, CLV, drawdown, калибровка и интервалы неопределённости.
- Walk-forward сравнение с market baseline и простыми моделями. Не продвигать ML, если она не превосходит baseline на независимом будущем интервале.

## Этап D: crowd intelligence
- Запись полного набора прогнозов, времени публикации и исходного URL/ввода.
- Отличать прогноз автора, подтверждённую ставку, непроверенную запись и рыночный сигнал.
- Учитывать минимальный размер выборки, копирование, зависимость источников и selection bias.
- Не автоматизировать платформы без явного разрешения и доступного API/экспорта.

## Этап E: виртуальные экспрессы
- Рассматривать размеры 2, 3, 5, 8 и 10 только после появления корректной модели совместных вероятностей.
- Разделять реальную котировку одного букмекера и теоретическое сочетание лучших котировок разных операторов.
- Проверять корреляции, market compatibility, сохранённые цены и дату фиксации.
- Settlement для переносов, отмен и void должен быть детерминированным и документированным.
- Не добавлять слабые исходы для достижения количества.

## Этап F: UX и надёжность
- Разделить Compose presentation, domain и data/repository слои.
- Room с миграциями, ViewModel + Flow; WorkManager только для согласованного фонового обновления.
- Экспорт/импорт и резервная копия локальных данных.
- Тесты математики, DAO, провайдеров, часовых поясов, settlement и offline UX.
- Понятные признаки источника, времени, свежести и качества данных.

## Принцип строгих утверждений
Нельзя выдавать ROI автора за будущую прибыль, crowd consensus за рыночную вероятность, разницу котировок за положительный EV, цену за доступную котировку, или единичный выигрыш за статистический успех.
