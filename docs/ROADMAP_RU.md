# Football Intelligence — архитектура и дорожная карта (Android, 0 ₼)

## Цель и ограничения
Личное приложение Android APK, без обязательного сервера, платных API и подписок. Цель — экспериментальная проверка статистических гипотез и запись **виртуальных** ставок, а не обещание дохода. Все данные хранятся только на устройстве.

## Этап A: рабочая локальная лаборатория (реализован код v0.1, сборка CI проверяется)
- Нативный Kotlin / Compose, Android SDK 35, minSdk 26.
- OpenLigaDB: запрос `GET /getmatchdata/{league}/{season}` через HTTPS, в приложении есть `bl1`, `bl2` за 2026 и `bl1` за 2025.
- SQLite для матчей, снимков коэффициентов 1X2, прогнозов и виртуальных одиночных ставок.
- Ввод **всех трёх коэффициентов** для математически корректного простого удаления маржи.
- Предматчевый timestamp, защита от записи новой виртуальной ставки после старта; допускается ручной ввод котировок только до матча.
- Расчёт ROI по завершённым виртуальным ставкам, не по всем открытым купонам.
- Отчётливо помеченные ограничения: отсутствие подтверждения реальной доступности цены и независимости капперов.

## Этап B: бесплатные данные без подписок
- OpenLigaDB для матчей поддерживаемых лиг (по доступным сезонам); добавить пользовательский выбор сезонов и справочник доступных турниров.
- Исследовать TheSportsDB *только согласно актуальной политике*; бесплатный публичный API не гарантирует коммерческого использования и полноты данных.
- Никаких скрытых endpoint, токенов из чужих приложений, обхода CAPTCHA, Google Play скрейпинга или массового доступа к защищённым сайтам.
- Импорт CSV/JSON через Android Storage Access Framework, включая ручное добавление котировок.
- Единый `canonical_match_id`, `provider_match_id`, `source_captured_at` и `ingested_at`.
- Дедупликация и контроль часовых поясов. Нет данных — честно пустой экран, без фабрикации.

## Этап C: честный статистический движок
- Full market mapping: 1X2 vs DNB vs Asian Handicap vs double chance; запрещать некорректное объединение.
- Последовательная история цены, защита от stale/future leakage, отдельный часовой пояс UTC.
- Приоритетная цена `best_at_bet_time` только если доказанно доступна.
- Метрики: hit rate, ROI, flat stake yield, Brier, log loss, CLV, drawdown + доверительные интервалы.
- Математические ориентиры: нормализация overround, логарифмическая регрессия, Elo, Poisson, Dixon–Coles при доступных данных.
- Crowd Consensus: рейтинг и уникальность первоисточника, учёт корреляции и копирования прогнозов.
- Полные тесты на исторических данных (walk-forward), без подглядывания в результаты.

## Этап D: виртуальные экспрессы
- 2 / 3 / 5 / 8 / 10 событий; только выбор матчей до начала.
- Купон у одного букмекера отдельно от теоретической комбинации лучших межбукмекерских цен.
- Контроль коррелированных матчей и рынков.
- Полный settlement, дробные линии, void, postponent и отмены по правилам выбранного виртуального рынка.
- Сравнение доходности экспрессов с одиночными ставками при сопоставимом обороте.

## Этап E: UX и надёжность
- Современный дизайн с 4 разделами: Матчи, Анализ, Купоны, История.
- Визуальный аудит данных: source, last-seen, stale badge, качество, протокол ошибок.
- Экспорт/импорт БД, резервная копия и восстановление.
- Тесты на Compose UI и DAO, пример фикстур без сетевого доступа.
- Локальные уведомления при наличии легальных и доступных источников; никакой зависимости от постоянно работающего внешнего сервера.

## Принцип строгих утверждений
Нельзя выдавать:
- ROI автора за гарантию будущей прибыли;
- наличие согласия капперов за реальную рыночную вероятность;
- рыночное расхождение за математически подтверждённый EV;
- демонстрационный коэффициент за реальную котировку;
- один красивый выигрыш за статистический успех.

## Требования к релизу
1. GitHub Actions компилирует debug APK (проверяем по статусу и artifact).
2. Нет ключей API / секретов в репозитории.
3. Функции корректно работают офлайн после загрузки календаря.
4. Каждая сохранённая котировка имеет источник и время.
5. При ошибке провайдера пользователь видит ошибку и сохранённые данные остаются доступны.
6. Settlement использует однозначный результат матча.
